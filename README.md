当前版本为 **2.5.0-qwen-rolling**。新版支持 Qwen 滚动排程、任务进度上报和协作式取消，并提供 Windows 的 A、B 端启动器。

- A 端先启动本地 Qwen 服务，再双击 [Start-A.cmd](Start-A.cmd)。B 端在 settings.json 中填入 A 的局域网地址，配置接入令牌后双击 [Start-B.cmd](Start-B.cmd)。完整步骤见 [Windows 使用说明](README.txt)。
- 本机体验规则调度可运行 `python launch.py --scheduler rules`。
- 最新的实测结果见 [2.5.0 单机与双机对照](reports/single-dual-comparison)，发版文件校验值见 [2.5.0 校验清单](MANIFEST-SHA256.json)。

## 立即运行

Windows 安装 Python 3.10+，在项目目录双击 **start.bat**，或执行：

```powershell
python launch.py
```

浏览器自动打开 http://127.0.0.1:8765 。默认启动两个真实的工作进程，它们都在本机，不能算成两台物理终端。规则模式仅依赖 Python 标准库；Qwen 调度模式另需 A 上的本地模型服务。

点击「运行 12 项演示任务」观察任务派发。点击「创建任务」输入巡检文本，再到任务详情查看真实分类输出。演示数据为合成事件，附加 CPU 负载单独计时。按 Ctrl+C 关闭协调端及其启动的工作进程。

## 已提供的成果

- 工作台：真实节点心跳、在线状态、执行任务、指标与动态网络图。
- 节点管理：暂停接收、恢复接收、管理员可信设置，远程节点默认不可信。
- 任务管理：创建、查询、取消、时限、四种策略、结果详情、CSV 导出。
- 执行机制：节点独立运行；25 秒租约、续租、最多 3 次执行尝试；旧租约结果拒收；协调端重启恢复。
- AI 模型：字符/双字特征的多项式朴素贝叶斯分类器，48 条自编合成训练样本。
- 调度：截止时间优先，估算等待、HTTP 往返、载荷传输与处理耗时；以实测运行耗时在线更新 EWMA。
- 实验：30 个种子、每次 240 项任务、四种策略、三类条件，共 86,400 条仿真任务记录。
- 参赛资料：delivery 目录的 PDF 与演示材料；docs 目录的可编辑正文、脚本与计划。

## 接入另一台电脑

2026年10月27日新增了[现场取证操作手册](docs/现场取证操作手册.md)和 `tools/field_evidence.py`。正式收集双机、需求与模型证据时优先按该手册操作：新记录保存在 `.local/field-evidence`，不会覆盖原基准，不自动进入公开交付包。

1. 两台电脑连接同一个可信局域网。协调端执行 `python launch.py --host 0.0.0.0` 或双击 start_lan.bat。
2. 在协调端运行 `ipconfig`，找到连接此网络的 IPv4 地址。仅在需要时允许 Python 在专用网络上接受入站连接。
3. 将代码复制到第二台电脑。把协调端 `.local/access_token` 的内容通过可信方式保存为第二台电脑的 `token.txt`。不要把令牌上传到网盘或代码仓库。
4. 第二台电脑在项目目录运行以下**整行命令**，把示例 IP 替换为协调端 IP：

```powershell
python -m suanlin.worker --coordinator http://192.168.1.100:8765 --token-file token.txt --name 办公室节点B --id office-b
```

5. 在协调端「算力节点」页核对实际设备，点击「设为可信」。默认任务仅使用已设为可信的节点。设置为可信代表管理员配置，不代表远程硬件证明。
6. 同时拍到两台电脑与工作界面，保存设备型号、网络配置、测试批次和导出 CSV，才形成真实多终端证据。

若端口已占用，使用 `python launch.py --port 8766`，执行端 URL 同步修改。若仅使用真实远程节点，协调端启动时加 `--workers 0`。每个执行进程必须有独立 `--id`；不传时自动生成。

HTTP 模式用于你们自己的可信实验网络。跨网络使用需另行加入 TLS、按节点区分的身份体系、密钥轮换与访问控制。当前共享令牌持有者具有管理权限，不适合开放给不可信用户。

## 复现实验和测试

```powershell
python -m unittest discover -s tests -v
python experiments.py
```

`results/simulation_raw.csv` 为全部仿真记录；`simulation_trials.csv` 为逐种子指标；`simulation_summary.json` 为均值、近似 95% 区间、配置、输入哈希与假设条件。仿真可以在无浏览器、无网络环境复现。

真实系统的逐次同机测试由以下命令产生，与仿真分开保存：

```powershell
python tools/benchmark.py --url http://127.0.0.1:8765 --token-file .local/access_token
```

该脚本会提交实际任务，预设为每种策略 5 次、每次 16 项，包含人工附加 CPU 负载。它不注入无线损伤，不代表不同物理设备。数据保存至 `results/local_benchmark_*`。运行前确保节点均处于正常接收状态。

## 成果边界

本项目已经实现应用层协同闭环。内置模型处理**文字事件**，不读取摄像头、图像、音视频或真实消防传感器，不应称为成熟巡检系统。合成训练集很小，模型分数未校准，输出需要人工复核。没有用户访谈、实际部署证明、软著、专利或真实多机结果时，不得声称已取得。

节点 HTTP 往返时间包含软件开销；带宽为配置值；传输字节仅统计派发 JSON 载荷，未计入协议头、心跳和重传。同机附加 CPU 负载与推理耗时分别记录，不能把整段计算时间写成神经网络推理时间。

当前未接入 6G 网络，未验证 6G 时延、带宽、可靠性或规模。6G 关联限于 AI 与通信融合及分布式算力协同的应用设计。仿真结果只适用于其假设条件。
