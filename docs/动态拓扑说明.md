# 动态拓扑与真实任务关联

更新日期：2026-11-12。位置：协同工作台“算力协同网络”。原动态横幅、指标和工作台布局保留。

## 使用方式

1. 提交任务，或运行原有演示任务。
2. 拓扑中央的协调端负责接收任务、选择节点与汇总结果；周围为实际登记的执行节点。同机进程与远程终端分别标注，不将进程数称为物理电脑数。
3. 点击执行节点图标，或通过下拉框切换节点，下方显示该节点正在运行的任务、执行阶段与上报进度。
4. 点击运行任务名称可打开详情；完成后，“最近完成”及图中节点下方提供结果入口。

图中最多显示四个节点，选择其他节点会将其显示到图中。下拉框可查看全部已登记节点，包括离线节点。选择在页面轮询期间保持。

## 数据来源与口径

- 数据来自已鉴权的 `/api/status`。节点、槽占用与状态沿用实际执行端记录；总体待调度、运行、完成数沿用全量任务统计。
- 新增 `topology.node_tasks`，为每个节点提供全部运行任务的轻量摘要与按完成时间倒序排列的最近三项完成记录。它独立于原任务列表的最近 200 条限制。
- 摘要不包含原始业务载荷、执行结果正文、租约或节点会话凭证。用户点击结果时，通过原有任务详情接口读取完整记录。
- 进度直接使用执行端心跳上报的 `done / total`，表示当前阶段，而非整个业务的总进度。文档检索中的单轮查询可以重新计数，不能解释为整体进度倒退。
- 无进度数据时显示等待上报，不按预计时长编造百分比。离线或超过 15 秒未更新的进度标记为已过期。短任务可能在两次轮询之间直接完成。
- 离线节点的运行记录在租约到期前保留，不将失联节点解释为空闲或仍正常运行。

## 动效含义

在线空闲连线保持静态；有实际运行任务时显示执行动效；完成时间距服务端当前时间小于八秒时显示近期结果接收动效。连线表示 HTTP 应用层关联，不是抓包数据、实时流量或 6G 网络链路测量。

动效遵循页面开关及系统减少动态效果设置。拓扑离开可视区域、页面进入后台时暂停任务连线动效；任务状态和结果入口仍可使用。

## 验证

后端新增检查覆盖：运行任务超出最近 200 条后仍可见、完成记录排序和三项上限、摘要不含原始载荷或租约、快照不会共享可变进度对象、离线节点记录保留。

浏览器在独立本地数据目录中使用两个真实本机执行进程，执行日志分析并观察实际心跳进度，验证节点切换、结果打开、轮询保持选择及离屏暂停。另以明确注入的布局状态检查多于四个节点、长名称、离线、过期进度和空状态；在 1440、768、390 像素宽度检查布局，并验证减少动态效果设置。

截图和浏览器检查摘要位于 `tmp/topology-review/`。这是界面与软件功能验证，不是新增的真实双机业务或网络性能实验。

协调服务需重启后才能提供新增摘要字段；前端兼容旧接口时，仅能从已有的最近 200 条任务中关联节点数据。
