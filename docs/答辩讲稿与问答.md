# 多终端任务调度系统答辩讲稿与问答

版本：2.4.1-slot-aware；材料更新：2026-11-12；实测日期：2026-11-11。数据以slot_aware报告和原始记录为准，不能把更新日期当成新增实测日期。

## 四分钟视频或路演讲稿

0分00秒至0分25秒：我们的项目是多终端任务调度系统，面向办公事件与CPU任务协同的设计假设。当多个任务集中到达，一台设备可能排队而另一台空闲。我们研究如何在时限与数据范围约束下分配任务，实际用户需求仍需访谈确认。

0分25秒至0分55秒：当前版本为2.4.1。已有两台真实电脑的测试记录，A、B各四个执行槽，峰值并发均达到四。A负责网页、协调与Qwen调度并参与执行，B只执行任务，不需要安装模型。若现场打开默认启动的两个本机进程，应明确那只是同机演示；我们用已有双机记录解释实测。

0分55秒至1分30秒：执行端实际运行日志分析、文档检索和脱敏压缩算法，输入是固定种子的合成业务数据。Qwen3.5-9B Q6_K只在A选择执行节点，不负责这些算法或巡检分类。原有48条合成样本训练的轻量分类器仍保留演示，不能宣称已经验证真实巡检准确率。

1分30秒至2分05秒：协调器先筛选在线且符合处理范围的节点，再向Qwen提供逐槽可用时间和各类型成本。模型最多一批决定八项，经整批重放与排程保护校验；未开始的任务可改派。记录区分原样Qwen、保护调整和规则回退。重任务排程等待最多八秒，模型等待计入总耗时，保护的效果不能全部算作模型贡献。

2分05秒至2分40秒：优化测试跨三个版本共450项正式任务、54项预热，全部一次执行完成。2.4.1最终24项持续任务复测为58.278秒，无规则回退；六项原样采纳，十八项采用保护方案。前轮同任务参考是A单机101.644秒、B单机87.646秒、双机规则51.559秒。它们是跨轮参考，规则仍更快，不能说Qwen必然优于规则。

2分40秒至3分15秒：任务完成不等于正确性全部验收。日志与检索跨机一致，压缩输出仍有差异，整体正确性验收未通过。网络只传任务规格，背景负载没有完全控制，持续吞吐仅一轮。旧的86400条仿真与320项同机基准单独保留，不能混入Qwen双机成绩。

3分15秒至3分45秒：项目对应AI与通信融合、分布式算力协同方向，目前使用普通HTTP，尚无6G空口或专网性能证据。后续优先解释压缩差异、补真实业务与需求访谈，再评估收益。开发和材料由生成式AI辅助，Qwen与llama.cpp为第三方资源，已披露用途和来源核对情况。

3分45秒至4分00秒：软件工程成员负责系统，电子信息工程成员负责组网与实验，两人共同复核。当前成果是可运行原型和可追溯的双机证据，尚不代表生产部署、商业收益或真实巡检质量已验证。

## 评委问答

### 为什么不用单机，双机是否已经测过

已测真实双机，最新配置A4/B4。24项持续任务前轮规则51.559秒，A单机101.644秒、B单机87.646秒；最终2.4.1 AI专项58.278秒是另一轮。任务少时单机可能更合适；现有结果不能证明真实办公室需求或所有负载下的收益。

### 两个工作进程是不是两台设备

默认python launch.py启动两个本机进程，不能算两台电脑。报告中的双机有不同主机、远程B任务和资源记录，见release-evidence；现场演示必须说明展示的是本机进程还是实测记录，不能用旧截图替代当前连接事实。

### AI在哪里，是否只有轻量分类模型

A运行Qwen3.5-9B Q6_K，通过本地llama.cpp接口辅助节点分配；B不运行Qwen。执行端处理CPU业务算法，轻量分类器只是保留的巡检演示。我们未训练Qwen，也不把EWMA或确定性保护称为深度学习。

### Qwen比规则更快吗，保护算不算回退

当前证据不支持Qwen超过规则。qwen为原样采用建议；qwen_guarded为采用排程保护方案，不等于模型原始分配，也不等于每项都改派；rules_fallback为异常或超限回退。最终24项为6/18/0，其中12项实际改变模型建议节点。2.4.0持续任务的16项回退保留，未删除。

### 450项是不是全由2.4.1完成

不是，它是本轮跨2.3.0参考、2.4.0优化、2.4.1复测的正式总量，不含54项预热。2.4.1只对标准6项、混合12项、持续24项各做一轮AI专项，共42项，未同时重测单机与规则。

### 完成率100%是不是正确性也100%

不是。450项一次执行完成说明执行状态；日志和检索跨机一致，压缩输出差异仍未解释，整体正确性验收未通过。Python/zlib差异仅是待核查方向，不能假定原因已经解决。

### 为什么旧材料有CPU循环，业务任务是否也靠循环加重

历史轻量分类演示附加SHA256循环来观察排队，循环单独计时。当前日志、检索、压缩任务执行真实CPU算法，无人工重复哈希循环；SHA256仅作正常完整性校验。合成输入仍不等于真实企业数据，网络只传规格。

### 6G在哪里，为什么仿真提升很大

对应IMT-2030的AI与通信融合、分布式计算方向，未接入6G空口或专网。旧仿真假设名义服务时间与队列已知，固定节点积压会放大差异；86400条记录只作参数敏感性分析，不含Qwen，不外推为真实网络性能。

### 算法是否首创，超时惩罚是否改变节点排序

不声称首创。截止时间优先、EWMA、租约和预测完成时间均有既有基础。规则的单调惩罚不改变同一任务内的排序；当前新增逐槽建模、整批保护和改派仍无最优性保证。未与Ray或KubeEdge做性能比较。

### 如何处理掉线、隐私和重复结果

独立租约校验与到期重排，最多三次尝试，旧结果拒收，可能重复计算。可信范围由管理员设置，远程默认不可信；共享令牌和HTTP仅用于可信实验网，没有硬件可信证明、TLS或多租户隔离，不能宣称合规认证。

### 商业价值有证据吗

没有客户、付费、规模化收益或真实业务试点证据。已有双机软件实验不能代替需求访谈、业务结果质量和维护成本评估。

### 生成式AI和第三方资源用了多少

Codex中的生成式AI辅助代码、测试、数据规格、方案、讲稿与材料构建；Qwen在运行时辅助调度，两者分开披露。Qwen及llama.cpp来源与许可入口见AI使用与第三方声明；本地Q6_K文件的精确下载来源、哈希及运行时构建号仍缺记录，不伪造。两名成员须复核事实、代码、引用与最终声明；AI不代替用户访谈或原始实测。
