## 回归中修复的问题

模型计算期间，新到紧急任务原先依赖 `created_at > captured_at` 判断。在时钟精度不足或时钟回拨时，该条件会漏掉新任务，导致旧方案仍然提交。现在在锁内记录排程开始时的任务 ID 集合，通过新任务是否属于该集合判断到达关系，不依赖墙上时钟顺序。

原紧急任务用例改为固定时间戳以稳定重现问题，另增加时钟回拨用例；修复前两项均失败，修复后通过。
