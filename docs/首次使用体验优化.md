# 首次使用体验优化

更新日期：2026-11-12。

## 问题与目标

原首页优先呈现算力、时限、网络拓扑和指标，自建任务又同时要求理解策略、数据范围与额外 CPU 负载。首次使用者缺少明确的第一步，提交后还需自行寻找结果。

本次按已确认的目标优化：先体验一个示例、理解系统用途，再提交自己的任务。体验成功的标志是用户独立完成“运行示例—看到分类与执行记录—填写自己的文本”，不要求先阅读调度机制。

## 现在的路径

1. 首页保留原动态横幅、实时指标、节点拓扑和工作空间动态；在原有操作按钮旁额外增加“新手引导”。点击后展开示例文字及“试跑一条示例”，不覆盖原组件。首次体验无需准备数据。
2. 点击后提交一项真实巡检文字分类任务：使用规则联合调度、仅可信节点、无附加 CPU 负载。重复点击有请求保护。
3. 自动打开任务详情；排队和运行状态持续更新，完成后优先显示分类结果、执行节点与耗时。
4. 从结果页点击“填写自己的文本”，进入简化表单。调度策略、数据范围、完成时限、CPU 附加负载收在高级设置中，保留有效默认值。
5. 自建任务提交成功后同样自动打开进度与结果。提交失败时保留输入并显示错误；隐藏的高级参数无效时会自动展开对应设置。

主页的指标、拓扑和调度机制继续直接展示，原有演示按钮与任务列表保留。日志分析、文档检索、脱敏压缩的任务模板入口随新手引导展开，并明确使用合成输入。部署页先呈现启动与使用步骤，再呈现面向 6G 的演进说明。

## 异常和状态

- 没有在线节点：禁用试跑，显示启动步骤入口。
- 所有节点暂停：提示恢复接收，并提供节点页入口。
- 没有可信可用节点：提示先核实设备并设置可信范围，不自动扩大数据处理范围。
- 请求尚未完成：显示正在提交，轮询不会重新启用提交按钮。
- 查看调度细节时收到刷新：保持展开状态，避免阅读被打断。
- 仅浏览页面不会自动提交任务。

## 本次验证与后续

已使用独立本地数据目录、实际协调服务及执行进程进行浏览器验证，覆盖示例执行、重复点击保护、结果到自建任务的衔接、业务模板、提交失败、无节点/暂停/不可信状态，以及 1440、768、390 像素宽度的五个页面和创建表单。检查记录在 `tmp/onboarding-review/checks.json`，截图同目录保存。

这些检查证明界面与操作路径可运行，不是已经完成用户易用性验证。后续应请未接触项目的人独立尝试，记录是否找到示例入口、是否理解结果、是否能提交自己的文本，以及在哪一步需要帮助。记录真实观察后再调整文案和布局。

网站仍是研究原型。首次示例使用合成样本训练的轻量分类器，输出需要人工复核；业务算法演示不支持上传自己的日志、文档或压缩文件。新的体验路径不构成真实业务质量或 6G 网络性能的证据。
