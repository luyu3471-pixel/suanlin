分工
A：协调网页、资源监控和本地Qwen3.5-9B Q6_K调度，兼任执行节点。
B：执行CPU日志分析、文档检索、脱敏压缩等任务；不需要安装Qwen。
本次验证配置为A四槽、B四槽。Qwen模型只监听A的回环接口 http://127.0.0.1:8086/v1，模型别名qwen3.5-9b。

当前两机升级
本机A已运行本版，B已运行兼容执行代码且并发为4；打包不会改变正在运行的服务。
若交给另一台电脑或项目主人，请先解压到独立目录，保留旧目录和数据备份。
已有系统需要等排队/运行任务清空再停止原执行器与协调器。新旧协调器不得同时使用同一数据库。
沿用原数据目录及其access_token，B沿用原令牌文件；不要将令牌放进代码仓库、聊天或软件包。

A启动（在解压后的项目目录执行）
先确认本地模型接口可用。现有A机器的正式数据目录为 D:\Suanlin-A\source\.local\office-field。
python launch.py --host 0.0.0.0 --port 8765 --workers 1 --concurrency 4 --scheduler qwen --data-dir "D:\Suanlin-A\source\.local\office-field" --no-browser
更换电脑时将数据目录替换为该机实际目录。全新部署可以使用 --data-dir .local/production，首次启动会生成新的令牌。
如仅测试规则调度，可改用 --scheduler rules，此时不需要启动Qwen。
网页：A本机 http://127.0.0.1:8765；本次局域网 http://192.168.5.43:8765。
需要跨机接入时确认局域网地址和防火墙允许B连接A的8765，不需要对B开放模型端口。

B启动（在B解压后的项目目录执行）
python -m suanlin.worker --coordinator http://192.168.5.43:8765 --token-file "<原B令牌文件路径>" --id office-b --name Office-B --concurrency 4
替换实际A地址和令牌路径；已有office-b须先退出，避免重复节点。全新节点需在A网页核实后设为可信。
从网页“算力节点”确认两台不同主机在线、并发槽为4。槽数由执行器参数控制，不能只改网页显示。
若用PowerShell Start-Process后台运行，请使用-WindowStyle Hidden，并保存PID和输出日志。

使用与复现
网页“创建任务”可选择业务类型、规模、时限与调度策略；任务详情显示模型建议、保护调整和实际节点。
python -m unittest discover -s tests -v
python tools/business_suite.py --url http://127.0.0.1:8765 --token-file "<A数据目录中的access_token路径>" --profile standard --rounds 3
python tools/business_suite.py --url http://127.0.0.1:8765 --token-file "<A数据目录中的access_token路径>" --profile mixed_deadlines --rounds 3
python tools/business_suite.py --url http://127.0.0.1:8765 --token-file "<A数据目录中的access_token路径>" --dataset benchmarks/business-v2.json --profile throughput --rounds 1
一次只运行一组性能测试。完整默认对照包含A单机、B单机、双机规则、Qwen路径。--policies ai仅用于专项复测。
