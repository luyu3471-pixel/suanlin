业务重任务 v1 / 2026-11-11

目标
在更长、类型不同的 CPU 任务上测量双机协同与 Qwen 调度的作用。
不预设 Qwen 胜过规则；保留 A 单机、B 单机、双机规则、双机 Qwen 全部结果。
Qwen 仅在 A 选执行节点，B 不安装模型。

三种实际执行算法
log_analysis：生成日志 → JSONL 序列化和解析 → 状态/告警词统计 → 设备聚合 → 精确P95排序 → 错误设备Top10。
document_search：构建文本二元词索引与文档频率 → 八条查询的TF-IDF式加权检索 → 排序返回Top10。
archive：记录脱敏 → 流式zlib 9级压缩 → 压缩率与压缩流SHA256校验。基准丢弃压缩文件，只保存统计/校验结果。
这些过程没有人工重复哈希循环。SHA256只用于正常的数据完整性校验。

数据的真实性边界
算法实际执行；输入由固定种子与人工编写文本生成，并非真实企业日志或文档。
输入生成耗时包含在任务时间内。两机独立生成同一输入，网络只传紧凑任务描述，没有测量大文件跨网络传输。
本版本没有DAG依赖编排、任意文件读取、摄像头识别或跨机切分模型。
归档完整性跨节点对照需使用兼容的Python/zlib版本；压缩算法版本差异可能影响压缩字节及摘要。

四档任务集：benchmarks/business-v1.json
smoke：6项小任务，先验证两机执行链路，不用于宣称性能优势。
standard：6项重任务，三类各2项，日志100万条/项、文档6万篇/项、压缩40万条/项。
heavy：6项更重任务，日志200万条/项、文档10万篇/项、压缩50万条/项。
mixed_deadlines：12项混合任务，大任务与1/10规模小任务交错；小任务时限30秒，大任务300秒。
每项任务保留独立seed；每种策略使用完全相同的输入规格。所有任务均无人工compute_loops。

A本机单次标准规模校准（非双机成绩）
日志100万条：26.753秒；检索6万篇：8.279秒；脱敏压缩40万条：8.762秒。
这比此前不足1秒的简单任务更能摊薄模型开销，但不证明Qwen比规则更优。
实测数据：results/business_calibration_20261111.json。

实现
worker声明支持的workload_kinds，旧执行端不会领取新业务任务。
三类任务分别学习每个节点的单位耗时，避免用同一个系数估计所有业务。
规则和AI使用同样的候选过滤、可信要求与保守内存预算。内存预算是估计，不是实测峰值。
Qwen输入增加业务类型、规模和资源特征；实际CPU时间、模型等待和回退都保留在结果中。
网页“创建任务”新增任务类型与业务规模；业务任务无需填写巡检文本，默认时限切为300秒。

启动与界面
新版独立目录启动示例：
python launch.py --port 8769 --workers 1 --concurrency 2 --scheduler qwen --data-dir .local/business-preview --no-browser
本机预览：http://127.0.0.1:8769 。模型仍为A本机 http://127.0.0.1:8086/v1。
正式双机需要A协调器与B执行端均升级。已有8765服务不会自动被此预览替换。
切换A前确认队列清空并备份数据；沿用原令牌，避免两个协调器同时访问同一数据库。

正式对照（只在A运行，替换令牌路径）
python tools/business_suite.py --url http://127.0.0.1:8765 --token-file "<原令牌文件>" --profile smoke --rounds 1
python tools/business_suite.py --url http://127.0.0.1:8765 --token-file "<原令牌文件>" --profile standard --rounds 3
python tools/business_suite.py --url http://127.0.0.1:8765 --token-file "<原令牌文件>" --profile mixed_deadlines --rounds 3
有余量再执行 --profile heavy --rounds 3。不同测试不得同时运行。
默认A节点local-1、B节点office-b，可用--a/--b指定。执行器要求不同主机且B来自远程，缺少能力则拒绝测试。
每种类型每节点先跑一项小预热，再轮换四种策略顺序。标准档3轮共72项正式任务，混合档144项。
首先保持A4/B1作为与上一轮相同的容量条件，再单独改变B槽数；不要同时改变代码、任务与槽数并归因于AI。
完整输入、接受的任务ID、每轮结果、失败和不完整记录位于 .local/business-tests。

验证
49项回归测试通过；三类真实HTTP任务均由Qwen选择节点并成功执行，另有网页创建/查看业务结果的实测。
上述校准仍是A本机验证，不应称为双机加速。
2026-11-11随后完成B升级及正式双机实测：264项正式任务、24项预热全部执行完成，66项AI策略正式任务均实际采用Qwen决策。
A四槽/B一槽；标准与混合场景各三轮，最大规模一轮。Qwen没有超过规则调度；压缩输出仍存在跨机差异，整体一致性验收未通过。
完整结论见 results/business_dual_20261111_report.txt，汇总见 results/business_dual_20261111_summary.json。
